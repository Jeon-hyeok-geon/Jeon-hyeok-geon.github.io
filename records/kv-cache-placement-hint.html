LLM/VLA KV Cache Offloading을 위한
시간 지역성 기반 SSD Placement Hint Middleware 설계

GPU와 DRAM에 모두 유지하기 어려운 KV Cache를 SSD로 offloading할 때, 문제는 단순히 어디에 저장할 것인가에서 끝나지 않습니다. 이 프로젝트에서는 다시 함께 읽힐 가능성이 높은 KV Cache를 묶어 배치하도록 storage에 hint를 내려보내는 방법에 대해 연구합니다.

RESEARCH QUESTION

비슷한 시점에 다시 읽힐 KV Cache를

restore I/O도 덜 흩어질까?

01

WHY THIS PROJECT

KV Cache는 점점 커지고,
모든 것을 GPU에 둘 수는 없습니다.

LLM, VLM, VLA는 추론 중 이전 계산 결과를 재사용하기 위해 KV Cache를 계속 생성합니다. 긴 문맥, 여러 요청, prefix reuse가 늘어날수록 cache도 빠르게 커집니다. GPU memory와 DRAM이 제한적인 edge device, embedded board, robot 같은 환경에서는 일부 cache를 storage hierarchy로 내려보내는 선택이 필요해집니다.

02

THE STORAGE PROBLEM

저장은 순서대로 했는데,
다시 읽는 순서는 순서대로가 아닐 수 있습니다.

KV Cache block마다 request, layer, token block, prefix reuse, 생성 시점과 최근 참조 시점이 다릅니다. 생성 순서만 기준으로 기록하면 나중에 함께 restore될 block들이 논리 주소 공간에서 떨어져 있을 수 있습니다. 이 연구는 그때 small random I/O나 fragmented I/O 같은 접근 패턴이 나타날 가능성을 검토하는 문제 가설에서 출발합니다.

03

EXISTING CONTEXT

Offloading의 흐름 위에서,
배치의 질문을 더해 봅니다.

기존 연구와 시스템은 KV Cache를 동적으로 관리하거나 GPU·CPU·storage를 함께 쓰는 방법을 다뤄 왔습니다. 이 기록은 그 흐름을 출발점으로 삼되, 특정 framework 전체를 수정하거나 FDP를 직접 구현하는 범위까지 확장하지 않습니다.

Offloading 자체보다, 어떤 KV Cache를 함께 놓을 것인가에 질문을 둡니다. 기존 시스템이 cache를 어디까지 내릴 수 있는지를 다룬다면, 이번 프로젝트에서는 offloaded KV Cache의 재사용 특성을 이용해 storage에 placement intention을 전달할 수 있는지를 살펴봅니다.

04

THE IDEA

KV Cache Metadata
→ Class
→ Placement Hint

이 프로젝트는 KV Cache tensor 자체를 분석하지 않습니다. 작은 metadata trace를 입력으로 받아 비슷한 재사용 특성을 가진 block을 class로 분류하고, 그 class를 storage placement hint로 변환하는 정책을 설계합니다.

05

PROPOSED FLOW

Middleware는 storage를 직접 제어하지 않고,
함께 놓을 data의 의도를 전달합니다.

구현 범위는 LLM/VLA inference framework의 KV Cache manager와 storage 계층 사이입니다. storage 내부 물리 위치를 지정하는 대신, 같은 class의 block이 같은 write stream, logical segment, 또는 placement group에 기록된다고 가정해 logical I/O pattern의 변화를 분석합니다.

06

HOW I PLAN TO TEST IT

작은 실제 trace에서
정책별 logical I/O를 비교합니다.

소규모 LLM 실행에서 일반 prompt, prefix reuse, multi-turn dialogue, batch request의 metadata trace를 수집하고, 여러 배치 정책을 같은 기준에서 비교합니다. 이 단계의 평가는 실제 SSD latency의 절대 개선을 증명하는 대신 host 관점에서 보이는 logical I/O pattern을 확인하는 데 초점을 둡니다.

WHAT THIS COULD GENERALIZE TO

시간 지역성, reuse, request relation 같은 metadata 기반 분류 구조는 특정 LLM 하나에만 묶이지 않는 방향을 목표로 합니다. 다만 이번 단계의 검토 범위는 small-scale LLM, limited workload, host-visible logical I/O에 한정됩니다. 여러 framework나 실제 FDP SSD에서의 일반성이 이미 증명된 것은 아닙니다.
